# DataMate 本地部署与模型配置指南

> 适用分支：`v1.10.0-datamate`（基于上游 SQLBot v1.10.0，已集成 sqlbot-xpack 商业包）
> 环境：Windows / Linux 通用，示例命令以 Windows PowerShell 为主

---

## 一、本地启动

分三部分：数据库 → 后端 → 前端。

### 1. 数据库（PostgreSQL + pgvector）

后端默认连接 `localhost:5432`，用户 `root` / 密码 `Password123@pg`，库名 `sqlbot`。最省事用 Docker：

```powershell
docker run -d --name sqlbot-pg -p 5432:5432 `
  -e POSTGRES_USER=root -e POSTGRES_PASSWORD="Password123@pg" -e POSTGRES_DB=sqlbot `
  pgvector/pgvector:pg16
```

> ⚠️ **建议用全新空库**。v1.4.1 老库里用旧 AES 加密的模型 API key 与 xpack 加密不兼容，直接迁移会导致模型调用失败（需在界面上重新保存模型密钥）。
>
> 建表无需手动操作——后端启动时 alembic 自动执行全部迁移（v1.4 → v1.10 共新增 054–071 十八个迁移）。

如果连接信息不同，在 `backend/.env` 里覆盖：`POSTGRES_SERVER` / `POSTGRES_PORT` / `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB`，或直接设置 `SQLBOT_DB_URL`。

### 2. 后端（Python 3.11 + uv）

```powershell
cd backend
uv sync --extra cpu          # 安装依赖；sqlbot-xpack 自动从 testpypi 拉取（pyproject.toml 已配置索引）
uv run uvicorn main:app --host 0.0.0.0 --port 8000
```

首次启动注意：

- **嵌入模型下载**：启动时会从 HuggingFace 下载 `shibing624/text2vec-base-chinese`（存到 `{LOCAL_MODEL_PATH}/embedding/`）。国内网络建议先设置：
  ```powershell
  $env:HF_ENDPOINT = "https://hf-mirror.com"
  ```
  或在 `backend/.env` 里设 `EMBEDDING_ENABLED=false` 跳过（会失去术语/训练数据的向量召回，本地调试可接受）。
- 数据目录默认 `/opt/sqlbot/...`，在 Windows 上落到当前盘符（如 `D:\opt\sqlbot\`），自动创建，无需干预。
- 缓存默认 `memory`，**不需要 Redis**（生产可在 `.env` 里切 `CACHE_TYPE=redis` + `CACHE_REDIS_URL`）。
- 启动成功会输出 `🚀 DataMate 开始启动...` 及各阶段耗时日志。

### 3. 前端（Node 18+）

```powershell
cd frontend
npm install
npm run dev
```

访问 **http://localhost:5173**，`frontend/.env.development` 已指向 `http://127.0.0.1:8000/api/v1`。

登录页依赖的 license-generator 脚本（`/xpack_static/license-generator.umd.js`）由后端 8000 端口的 xpack 提供，前端会自动去后端加载，无需额外配置。

**默认账号**：`admin` / `DataMate@123456`（`DEFAULT_PWD`，见 `backend/common/core/config.py`）

### 4. 可选组件（本地开发可不启动）

| 组件 | 端口 | 用途 | 启动方式 |
|---|---|---|---|
| g2-ssr | 3000 | MCP 服务端出图（柱状图/折线图/饼图） | Node + PM2，见 `g2-ssr/` |
| MCP Server | 8001 | Model Context Protocol 服务 | `uv run uvicorn main:mcp_app --port 8001` |

## 二、模型配置

两类模型的配置位置完全不同：**LLM 界面配、库里存；Embedding 环境变量配、本地跑**。

### 1. 大语言模型（LLM）——Web 界面配置，存数据库

**配置入口**：登录后 → 系统管理 → **AI 模型**（管理员菜单，前端页面 `frontend/src/views/system/aimodel/`）

- 存储在 PostgreSQL 的 **`ai_model` 表**（模型定义 `backend/apps/system/models/system_model.py`）
- 支持 OpenAI 兼容协议、火山引擎等 supplier，配置 base_url、api_key（密钥经 xpack 加密存储）、模型名、温度等参数
- 通过 `ai_model_workspace_mapping` 表关联到工作空间；每个工作空间可设默认模型
- 运行时由 `backend/apps/ai_model/llm.py` + `model_factory.py` 按会话动态实例化（LangChain ChatOpenAI）

**LLM 不写在任何配置文件里**——启动后必须先在界面上添加至少一个模型才能问数。

> ⚠️ `ai_model` 表的 api_key 加密存储。若复用 v1.4.1 老库，旧密文用旧 AES 加密，xpack 解不开，需在界面上重新保存一遍每个模型的 API Key。

### 2. 嵌入模型（Embedding）——后端配置文件/环境变量

代码固定使用本地 HuggingFace 模型，配置项在 `backend/common/core/config.py`，可通过 `backend/.env` 覆盖：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `EMBEDDING_ENABLED` | `true` | 总开关，false 则不下载/不加载嵌入模型 |
| `DEFAULT_EMBEDDING_MODEL` | `shibing624/text2vec-base-chinese` | 模型名（缓存 key） |
| `LOCAL_MODEL_PATH` | `/opt/sqlbot/models` | 模型文件存放目录 |
| `EMBEDDING_DEFAULT_SIMILARITY` | `0.4` | 默认相似度阈值 |
| `EMBEDDING_TERMINOLOGY_SIMILARITY` | 同上 | 术语召回相似度阈值 |
| `EMBEDDING_DATA_TRAINING_SIMILARITY` | 同上 | 训练数据召回相似度阈值 |
| `EMBEDDING_*_TOP_COUNT` | `5` | 各类召回条数 |
| `TABLE_EMBEDDING_ENABLED` / `TABLE_EMBEDDING_COUNT` | `true` / `10` | 表结构向量召回（v1.10 新增） |

加载逻辑在 `backend/apps/ai_model/embedding.py`——实际加载的是 `{LOCAL_MODEL_PATH}/embedding/shibing624_text2vec-base-chinese` 这个**写死的本地目录**，首次启动时从 HuggingFace 下载，之后离线使用。

嵌入模型**不支持在界面上切换**，向量存在 pgvector 里（术语、数据训练、表结构三类）。

## 三、常用环境变量速查（backend/.env）

```ini
# 数据库
POSTGRES_SERVER=localhost
POSTGRES_PORT=5432
POSTGRES_USER=root
POSTGRES_PASSWORD=Password123@pg
POSTGRES_DB=sqlbot
# 或直接指定完整连接串（优先级更高）
# SQLBOT_DB_URL=postgresql+psycopg://user:pwd@host:5432/sqlbot

# 嵌入模型
EMBEDDING_ENABLED=true
LOCAL_MODEL_PATH=/opt/sqlbot/models

# 缓存
CACHE_TYPE=memory
# CACHE_REDIS_URL=redis://localhost:6379/0

# 日志
LOG_LEVEL=INFO
SQL_DEBUG=false

# 前端地址（CORS）
FRONTEND_HOST=http://localhost:5173
```
